# DeskReview — согласование чертежей и 3D в браузере

> Рабочее название продукта: **DeskReview** (репозиторий может называться `3d_viewer`). Для компании — использование в текущем виде под этим именем.

Веб-приложение для просмотра и согласования **PDF-чертежей** и **3D-моделей** в браузере: получателю не нужны AutoCAD, КОМПАС-3D и т.п. Поддерживаются **аннотированные скриншоты**, **PDF-отчёт** с измерениями, **мультимодельная сборка** с сохраняемыми сопряжениями по плоскостям, отдельные деревья файлов **PDF/3D** и облегчённый режим **«Производство (QR)»**.

**Версия фронта:** 1.11.0 (см. `viewer/package.json`). Меню **DeskReview**; замечания **PDF/3D** (v1.8.0); Диск → открытие во вьювере (v1.8.2); дерево деталей, каркас, изоляция (v1.9.0); разнесение, orbit pivot, STL (v1.10.0); **CAD-рамка выделения** (window/crossing), **Esc — сброс выделения**, доработки **измерений** (расстояние, линейные размеры), **галерея скриншот-отчёта** (v1.11.0).

### Верхняя панель (`ViewerToolbar.vue`)

- Меню **DeskReview**: **Файл**, **Режим**, **Логи**, **Скриншот-отчёт** (счётчик, **«Все скриншоты»** — галерея с превью, сортировкой и скачиванием), **Телемост**; **Ctrl+S** — замечания PDF или JSON замечаний 3D; **Ctrl+Z** — отмена в PDF или последний сдвиг детали в 3D.
- См. [notes/session-2026-05-19-deskreview-ui-product.md](notes/session-2026-05-19-deskreview-ui-product.md).
- Открытие PDF/3D — из **Файл**, дерева **Яндекс.Диска** или drag-and-drop.

## Зачем это нужно

На рынке обычно разделены:

- **PDF-редакторы** — не заточены под инженерный цикл «открыл чертёж → отметил на 3D → в отчёт»;
- **CAD-просмотрщики** — отдельные файлы и лицензии, редко единый сценарий «ссылка в чат → браузер → скриншот с подписью → один PDF».

Этот проект — **«инженерный мост»** в одной странице:

| Возможность | Описание |
|-------------|----------|
| **PDF + 3D** | Одна вкладка: чертёж и модель рядом. |
| **Скриншоты и отчёт** | Редактор фигур/текста, сборка **одного PDF** (jspdf), блок измерений. |
| **Сборка** | До нескольких моделей в сцене, **связи по плоскостям** (совпадение, расстояние, симметрия по ширине), повторное применение после перетаскивания. |
| **2D-first сценарий** | PDF и 3D выбираются независимо, без обязательной автопривязки. |

3D — **усиление** к PDF, а не обязательный слой: фронт можно запускать **без сервера** (тогда нет серверной конвертации STEP по API; STEP всё равно можно грузить через **WASM** в браузере в пределах лимита размера).

## Возможности 3D-сцены (`Viewer3D.vue`)

### Форматы и загрузка

- **STL**, **STEP** (`.stp`, `.step`), **IGES** (`.igs`, `.iges`), **GLB/GLTF**.
- **STL:** загрузка в браузере; при нескольких несвязанных телах — **разбиение по связности** и дерево деталей; опционально `*.meta.json` и авто-раскраска (слитая сборка в одном STL — одна деталь, для дерева/цветов лучше STEP).
- **STEP/IGES:** сначала запрос **серверной** конвертации (CadQuery + trimesh → GLB); при недоступности или ошибке — **opencascade.js (WASM)** в браузере.
- **Лимит STEP/IGES на фронте:** **30 МБ** (больше — загрузка не выполняется, сообщение в лог).
- На сервере отдельный лимит для конвертации — см. [server/README.md](server/README.md).

### Навигация и вид

- **TrackballControls**, меню **ориентаций**, режим **«Перпендикулярно к грани»** (клик по грани + кнопка).
- **ПКМ по детали:** центр вращения переносится на точку под курсором (без сдвига кадра при перетаскивании; клик под контекстное меню не дёргает камеру).
- **Сетка пола** (вкл/выкл), размер от габаритов модели.
- Во время вращения камеры — снижение `pixelRatio` и throttling тяжёлых расчётов (hover и т.д.).

### Материалы и освещение

- Режим **«С освещением» (lit):** **MeshPhongMaterial**, направленные источники + ambient/hemisphere; **карты теней** (мягкие PCF) от ключевого света, подстройка теневой камеры под **габариты сцены**; баланс fill-света, чтобы тени читались на **светлой** модели.
- Режим **«Без шейдинга» (unlit):** уплощённый вид (Lambert + emissive), **тени отключены** для скорости и предсказуемого вида.
- **Оттенок / яркость модели** — быстрый слайдер без смены типа материала.
- **Каркас (кнопка в шапке):** линии по контуру деталей (`EdgesGeometry`); яркость линий — слайдер/поле. Грани при каркасе скрыты — видны только рёбра.
- **Дерево деталей (левая панель):** группы по именам из модели; клик — выделение; **рамка на сцене** (CAD): слева→направо — только полностью внутри (синяя), справа→налево — пересечение (зелёная); **Ctrl/Shift** — добавить к выделению; **Esc** — снять выделение; яркая подсветка выбранных деталей; **двойной клик** — изоляция; повторный двойной клик — показать все.
- **Прозрачность (ПКМ по детали):** 100/75/50/25/10% для геометрии под курсором, 50% для строки в дереве или всей сборки; сброс — для детали или всей модели.
- **Измерения и сборка** на изолированной детали: луч игнорирует скрытые меши и линии каркаса.
- **Память:** освобождение моделей при unmount, очистка WASM FS после STEP, dispose клонов миниатюр и unlit-материалов. Модели в **библиотеке** (не в сцене) по-прежнему держат полную геометрию в RAM — удаляйте ненужные через «Удалить модель».
- **Разнесение (explode):** слайдер 0–100 % от **максимального габарита** модели; якорь — крупнейшая деталь; остальные группы расходятся радиально и при взаимной близости; единицы сцены в **мм** (авто-масштаб м→мм при импорте).

### Сечение и измерения

- **Сечение:** выбор оси/смещение, клик по грани для ориентации плоскости, фиксация/снятие.
- **Измерения:** **Расстояние** — прямое расстояние между двумя точками (live-preview); **Между гранями** — линейный размер ГОСТ с выносом, перетаскивание выносной линии, подсветка опорных граней; привязка (грань, вершина, ребро и др.).
- **Журнал измерений** — таблица в левой панели: восстановление по клику, удаление строки, подписи по центру выносной линии.

### Сборка (несколько моделей)

- Выбор **источника** и **опорной** модели из списка загруженных **в сцене**.
- Типы сопряжений: **плоскость ↔ плоскость**, **по расстоянию**, **симметрия по ширине** (четыре плоскости: две на базе, две на детали).
- **Пошаговый выбор граней** подсвечивается в сцене (треугольник грани или маркер плоскости).
- После **«Применить сопряжение»** связь сохраняется в таблице; при **перетаскивании** детали связи **пересчитываются**.
- Таблица **«Зафиксированные связи»:** клик по строке подсвечивает плоскости этой связи в 3D; повторный клик снимает подсветку; удаление связи — кнопка в строке.

### Прочее в 3D

- **Метрики сцены:** площадь поверхности, объём, число треугольников (для моделей в сцене).
- **Экспорт:** GLB, STL.

### PDF (вкладка рядом с 3D)

- Просмотр через **PDF.js**: тайлы, зум (Ctrl+колёсико), панорама, миниатюры страниц.
- Вкладка **«Замечания»**: стрелки, линии, полилинии, рамки, эллипсы, текст; режим **◇** — перемещение и узлы; Esc — сброс выделения; **Ctrl+Z** — отмена последнего действия на слое.
- **Сохранить замечания проекта** (Ctrl+S) — PDF + `*.deskreview-markup.json` (слой можно снова открыть и править в DeskReview).
- **Сохранить с замечаниями** — один PDF с пометками на листе (для Acrobat, почты, печати).
- Автоподгрузка слоя: черновик в IndexedDB, JSON рядом при открытии/перетаскивании пары файлов.
- **Пометки вкл/выкл** — только скрыть оверлей на экране.
- Скриншоты 2D, редактор аннотаций, **отчёт jspdf** (отдельно от полного чертежа с замечаниями).

Подробнее: [notes/session-2026-05-19-pdf-markup-removable-layer.md](notes/session-2026-05-19-pdf-markup-removable-layer.md), [notes/session-2026-05-19-pdf-markup-export.md](notes/session-2026-05-19-pdf-markup-export.md).

### Производство (QR)

- Отдельный режим интерфейса для мобильного сценария.
- Заготовка страницы модуля с QR и списком ссылок на чертежи из дерева PDF.

### Логирование

## Запуск

### Всё сразу (Windows)

Из корня репозитория:

```batch
run.bat
```

Поднимает **два окна**: backend (**http://localhost:8000** — чат, API, конвертация STEP) и фронт (**http://localhost:5173**). Между ними пауза ~4 с, чтобы API успел стартовать. Без сервера чат и вход в коллаборацию недоступны (`ERR_CONNECTION_REFUSED` на `:8000`).

### Только фронт

```bash
cd viewer
npm install
npm run dev
```

Без сервера: нет серверной конвертации STEP и нет данных спецификации с API; STEP до лимита — через WASM в браузере.

### Только сервер

```powershell
cd server
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Health: `http://localhost:8000/api/health`  
Подробности API: [server/README.md](server/README.md).

### Этап 1 — фундамент совместной работы
- БД (PostgreSQL): `users`, `projects`, `project_members`, `chat_channels`, `chat_messages`, `chat_attachments`, `message_reads`, `audit_log`.
- Авторизация: JWT access/refresh, роли `owner/editor/viewer`, проверка membership на API и realtime.
- API-каркас: `/auth/*`, `/projects/*`, `/chat/*`, базовые health/status.
- Миграции и эксплуатация: Alembic/Flyway, backup/restore, базовые логи и метрики.
- *Сейчас в коде:* SQLite + JWT + чат + Yjs по WebSocket (база для этапов 3 и 7).

### Этап 2 — связка PDF и 3D в проекте
- Реестр проекта (`project_index`) и автосопоставление PDF ↔ 3D по правилам именования.
- Ручная привязка/перепривязка файлов в UI.
- Открытие связанной пары в 1-2 клика.

### Этап 3 — чат, контекст и слой замечаний *(частично: статусы PDF/3D)*
- Вложения скриншотов из PDF и 3D (частично есть: редактор скриншота → чат).
- Контекст сообщения: страница PDF, камера/деталь 3D, файл проекта.
- Realtime-доставка сообщений и статусы прочтения.
- **Живые аннотации на точке:** PDF — этап **3c**; 3D — этап **3d** (якорь на грани + камера + экранная разметка).
- **Замечания как сущности** (не только строка в чате): статусы `open` / `answered` / `accepted` / `rejected` — **в коде** для пометок PDF (sidecar) и замечаний 3D (JSON): фильтр, бейдж, описание; **дальше:** ответы, исполнитель, `rev`, связь с чатом.
- Единая панель **«Замечания»** с деревом (PDF и 3D); скриншот с разметкой — в чат/отчёт, не основной способ навигации по 3D.

### Этап 3c — разметка PDF и экспорт *(v1.7.0+, статусы в v1.8.0)*

> **Сейчас в коде:** оверлей на страницах, инструменты (стрелка, линия, полилиния, рамка, овал, текст, выделение), IndexedDB, экспорт «замечания проекта» + «с замечаниями на листе»; у каждой пометки — **статус** (`open` / `answered` / `accepted` / `rejected`), описание и фильтр в табе «Замечания». **Дальше:** Yjs/чат, полная модель Comment. Детали: [notes/session-2026-05-19-pdf-markup-export.md](notes/session-2026-05-19-pdf-markup-export.md).

**Режим работы**
- Один автор или несколько (цвет/аватар участника, по образцу Figma Jam).
- Слой разметки **на каждой странице** открытого PDF (десятки и сотни листов), не только на скриншоте текущей страницы.
- Инструменты: стрелки, рамки, эллипсы, текст (переиспользовать модель из редактора скриншота); замечания как сущности с автором и временем.

**UI: левый таб «Замечания» в `PdfViewer`** (этап 9 + 3c)
- Дерево: группы **«Стр. N»** → замечания на листе (вложенность); в названии — номер страницы.
- Клик → страница + область + зум + оверлей; блок **путь / Открыть / Добавить** для картинок на чертеже.

**Оверлей (первый подэтап разработки)**
- SVG/canvas поверх `PdfViewer`, координаты **нормализованные** (0…1 от размера страницы) — не ломается при зуме.
- Хранение черновика: IndexedDB (ключ: хеш/имя PDF + проект); флаг `markupDirty` при любой правке.
- Рендер оверлея только для видимых страниц (виртуализация при 100+ листах).

**Экспорт PDF** *(реализовано)*
- **Сохранить замечания проекта** — чистый PDF + `{имя}.deskreview-markup.json`.
- **Сохранить с замечаниями** — один PDF с отрисовкой на страницах (**pdf-lib**).
- Имена с датой: `{база}_с_замечаниями_…pdf` / `{база}_замечания_запечённые_…pdf`.
- Отдельно от отчёта **jspdf** со скриншотами.

**Несохранённые изменения**
- При закрытии вкладки / обновлении страницы — **свой модальный диалог**: «Сохранить замечания?» / «Не сохранять» / «Отмена»; пока диалог открыт — не менять документ и не уходить с проекта без выбора.
- Дополнительно `beforeunload` (стандартное предупреждение браузера; полностью заблокировать закрытие вкладки без ответа современные браузеры не позволяют).
- Автосохранение черновика в IndexedDB по таймеру — восстановление после случайного закрытия.

**Коллаборация (после оверлея и экспорта)**
- Синхронизация слоя разметки через Yjs / API (этап 8); выгрузка итогового PDF на Яндекс.Диск (этап 5).
- Скриншот страницы с разметкой в чат — как сейчас; полный PDF с замечаниями — отдельный артефакт.
- Общая модель **Comment** с этапом **3d** (одна схема JSON, разный контекст: `pageNumber` vs `viewState`).

### Этап 3d — замечания на 3D «как eDrawings» *(v1.8.0 — базовый screenLayer)*

> **Сейчас в коде (v1.8.0):** таб «Замечания» — список, «+ Замечание», восстановление камеры, JSON + IndexedDB, Ctrl+S; статусы и описание; **якорь 3D** (маркер на детали); **screenLayer** — те же инструменты, что в PDF (◇ навигация модели / рисование), выделение и растягивание; **картинка** — вставка, перетаскивание, зум колёсиком (в JSON пока `dataUrl`, на диск — планируется папка `*_assets`). Оверлей скрывается при отклонении камеры >9°. **Дальше:** экспорт assets на диск, Yjs. Детали: [notes/session-2026-05-19-3d-remarks-edrawings.md](notes/session-2026-05-19-3d-remarks-edrawings.md).

**Режим просмотра замечания — живая 3D-сцена**
- Клик в дереве → восстановить **камеру** (`viewState`) и показать **оверлей разметки** поверх живого канваса `Viewer3D`.
- **Не** подменять сцену PNG-snapshot (снимок — только превью в списке, чат, архив).

**Два типа привязки (важно при орбите)**
| Слой | Привязка | При смещении камеры |
|------|----------|---------------------|
| **Якорь 3D** (`anchor3d`) | Точка на детали (`modelId`, local point, normal) | Маркер остаётся на геометрии |
| **Экранная разметка** (`screenLayer`) | Координаты 0…1 viewport + сохранённый `viewState` | Совпадает с моделью только в том же ракурсе; при отклонении — скрыть оверлей и показать подсказку / кнопку **«Вернуть вид замечания»** |

**UI: левый таб «Замечания» в `Viewer3D`** (этап 9 + 3d)
- Дерево комментариев; клик → живая сцена + камера + разметка (не вкладка «Телемост» и не общий чат).
- Блок: **путь к картинке** → **Открыть** → **Добавить** (вставка в область модели в текущем ракурсе).
- Кнопки «Сборка» / «Измерение» в шапке 3D переключают табы **Сборка** / **Измерения**; плавающие панели с канваса убрать.

**Файлы на диске (GLB не изменяем)**
```
Модуль_01.glb
Модуль_01_замечания_19.05.2026_14-35.json
Модуль_01_замечания_19.05.2026_14-35_assets/
  c-001_attached.jpg
  c-001_thumb.png          ← опционально, не для навигации
```
- JSON связывается с GLB по `fileName` (+ `sha256` позже); картинки — `dataUrl` в черновике / IndexedDB, при экспорте на диск — папка `*_assets/`.
- При открытии GLB — автопоиск `{имя}_замечания_*.json` или явное «Открыть замечания».

**Сохранение и защита от потери**
- Имя: `{имя_модели}_замечания_{дд.мм.гггг}_{чч-мм}.json` (+ папка assets).
- Общий флаг `remarksDirty` (PDF ∪ 3D) → модалка «Сохранить замечания?» / `beforeunload` / автосейв в IndexedDB (как в 3c).

**Коллаборация (позже)**
- Несколько ревьюеров — отдельные JSON или общий файл + автор в комментарии (как `.markup` у разных ревьюеров в eDrawings).
- Синхронизация через Yjs / API (этап 8); выгрузка пакета на Яндекс.Диск (этап 5).

### Этап 4 — QR, производство и манифест проекта *(запланировано)*
- Стабильный URL навигации (`/p/{token}`), не сырой путь на Диске; маппинг токена → актуальные файлы при переезде папок.
- **Отдельный QR на каждый профиль** модуля (минимум 4 на модуль для гравировки); слоты `P1`, `P2`, … → компонент входящего состава → чертежи.
- Манифест от проектировщика (YAML/JSON): проект → фасады → модули → `profiles` + `components`; сервис создаёт дерево на Яндекс.Диске и регистрирует токены.
- Пакет для производства: таблица слот / подпись / файл QR (PNG/SVG); регламент размера и коррекции ошибок для гравировки.
- Mobile-first лендинг по QR: объект, фасад, модуль, профиль, ссылки на PDF и папку/комплект чертежей (без OAuth в цеху — публичная выдача или прокси).
- Перегенерация QR только при смене токена (редко); обновление файлов на Диске без смены гравировки.

### Этап 5 — интеграция с Яндекс.Диском *(частично есть: дерево, OAuth, публичная папка)*
- Регламент структуры каталогов: проект → фасад → подсистемы (модули / формообразователи / облицовка) → модуль → слоты `чертеж/`, `модель_3d/`, `спецификация/`, `cad_исходники/`.
- Синхронизация с множеством корневых папок по модулям; опционально `_meta/manifest.json` на проекте.
- Инкрементальное обновление по etag/hash/mtime; статусы синка и обработка конфликтов.
- Папка `DELIVERY` (только PDF + GLB) для полевого доступа по QR.

### Этап 6 — подготовка 3D на стационаре → Диск *(частично v1.8.2)*
- **В вебе (v1.8.2):** клик по файлу в дереве Диска → загрузка через API сервера; для STEP/IGES в папке автоматически берётся одноимённый **GLB**, если он лежит рядом.
- **Дальше:** десктопный/пакетный конвертер (Blender / OCCT CLI), выгрузка в `модель_3d/`, `meta.json`, индикация устаревания GLB относительно STEP.
- Режим «watch-папка» или скрипт по регламенту именования для BIM/КОМПАС-отдела.
- Индикация устаревания: GLB на Диске старше исходного STEP/FBX.

### Этап 7 — качество 3D и серверная конвертация *(запланировано)*
- Серверный пайплайн STEP с **XCAF/цветами** (не только CadQuery→STL→один меш); выравнивание с логикой браузерного `stepLoader.ts`.
- Сохранение цветов из STEP после `Transfer` (читать `ColorTool` до подстановки палитры по имени).
- Опционально: очередь конвертации на офисном сервере/ноутбуке (Blender FBX→GLB) для тяжёлых моделей.
- Revit: регламент экспорта FBX; целевой контейнер доставки в веб — **GLB**.

### Этап 8 — совместный просмотр в реальном времени *(запланировано)*
- На базе уже имеющегося **Yjs + WebSocket**: синхронизация **страницы PDF** и **камеры 3D** («ведущий» и подписчики).
- Awareness: кто смотрит тот же документ (цвета участников уже частично есть).
- Без полного CRDT трансформов сборки на первом шаге; приоритет — «все видят одно и то же» + актуальный список замечаний.
- Совместное редактирование аннотаций на PDF (**3c**) и 3D (**3d**) — после оверлея и sidecar JSON.

### Этап 9b — измерения: два режима *(в коде, UX v1.11.0)*
- **Расстояние** (`distance`): два клика или live-preview → **прямое расстояние** между точками (без треугольника разложения).
- **Линейный размер** (`cad-linear`): три плоскости (1-я, 2-я, плоскость выноса) → размер между параллельными гранями, **выносные линии** и **стрелки ГОСТ**, перетаскивание выноса, подсветка опорных граней, цвет **`#ffad5b`**.
- Прочие типы (радиус, дуга, …) — во вторичном списке, не смешивать с основными двумя режимами в UX.

### Этап 10 — сводки и AI *(запланировано, низкий приоритет)*

- Опционально AI-сводка по замечаниям и изменениям на Диске — только после политики данных (on-prem / без утечки проектной документации во внешние API).
- Уведомления ГИПу: «N блокеров по фасаду X» перед совещанием.

### Этап 11 — BIM-аудит модели (идеи [bimatter IFC-viewer](https://dzen.ru/a/ZLjxxf7N-E5a__IT)) *(запланировано)*
Не обязательный нативный IFC в браузере (Revit → FBX/GLB + `meta.json` достаточно). Берём **поведение просмотрщика**:

| Идея bimatter | Наша реализация |
|---------------|-----------------|
| Дерево проекта (фасад → модуль → деталь) | Дерево Яндекс.Диска + манифест (этап 4–5) |
| Свойства выбранного элемента | Панель «Свойства» из `meta.json` / позже IFC |
| Несколько сечений одновременно | Расширить текущее сечение (сейчас по сути одна плоскость) |
| Скрыть / изолировать / показать всё | ПКМ + дерево (частично есть «Скрыть деталь») |
| Перекраска по атрибуту (группа, статус) | По полям meta, независимо от цвета меша в GLB |
| Выделение рамкой (Shift) | **В коде (v1.11.0):** window/crossing на сцене; слои и назначение — вкладка «Выделение» |
| Экспорт в Excel | Спецификация / реестр элементов с атрибутами |
