# Архитектура Диска, QR по профилям, манифест — черновик для дополнения

Дата начала конспекта: 2026-05-14. Файл для продолжения обсуждения и дополнения требований.

---

## 1. Роли хранилищ

| Слой | Назначение |
|------|------------|
| **Яндекс.Диск** | Источник истины по файлам проекта: чертежи (PDF/DWG), 3D (STEP/FBX/GLB и т.д.), спецификации (XLS), исходники CAD (CDW, RVT). |
| **Сервер приложения** | OAuth к Диску, конвертация тяжёлых форматов, коллаборация (SQLite, чат, `uploads`), метаданные. Реализация сегодня: `server/yadisk_routes.py`, дерево в `App.vue` / `YandexDiskTree.vue`. |
| **Браузер** | Просмотр поддерживаемых форматов, дерево Диска через API. |

Принцип: Диск = каталог проекта; приложение навигирует и открывает файлы (плюс производные GLB на сервере при необходимости).

## 2. Рекомендуемая иерархия папок на Яндекс.Диске

Структура задаётся **именами каталогов** (Диск не знает «семантики», только дерево).

```
/<Клиент или организация>/
  /<Код проекта>_<Имя>/
    _meta/                          # README, регламент имён, опционально manifest.json
    01_Фасады/
      FCD_1-5_<Кратко>/
        01_Модули/
          M-001_<Название>/
            чертеж/
            модель_3d/
            спецификация/
            cad_исходники/
          M-002_...
        02_Формообразователи/
          ...
        03_Облицовка/
          ...
      FCD_5-1_.../
      FCD_A-Б_.../
```

Подсистемы **Модули / Формообразователи / Облицовка** — три параллельных дерева под фасадом с одинаковой логикой внутри.

**Слоты файлов в модуле (шаблон):**

| Слот | Файлы | Заметка |
|------|--------|---------|
| Чертёж для согласования | PDF (+ опционально DWG) | PDF во вьювере |
| 3D для веба | GLB/glTF | после конвертера |
| 3D источник | STEP, FBX, JT | сервер / WASM |
| Спецификация | XLS/XLSX | |
| Исходники CAD | CDW, RVT | не во всех вьюверах |

Префиксы (`01_`, `FCD_`, `M-001`): сортировка и уникальность повторяющихся имён («Модуль М-1» в разных фасадах).

Опционально: `_meta/manifest.json`, папка `DELIVERY` только PDF+GLB для поля.

## 3. QR на каждый профиль (гравировка на каркасе модуля)

**Требование:** на каждый профиль **свой** QR (минимум 4 на модуль — производство). QR как навигатор с телефона до комплекта чертежей **входящего компонента** (или связанной папки).

### 3.1 Роли объектов

- **Модуль** содержит несколько **позиций профиля** (слотов гравировки): `P1`, `P2`, …
- Чертёж и файлы на уровне **компонента входящего состава**; несколько профиль-слотов могут ссылаться на один `component_id` (один чертёж — два QR допустимо для трассировки физической детали).

### 3.2 Стабильный URL (не сырой путь Диска)

QR кодирует **URL вашего сервиса** с **непрозрачным токеном**:

- Пример: `https://view.<домен>/p/a8f3k2x9`
- В БД: `nav_token` → `(project, facade, module, profile_slot, component_ref → цели на Диске)`

При переезде папок на Диске обновляется **маппинг**, физическая гравировка не меняется.

**Не класть в QR:** полный `disk:/…`; зависимость только от OAuth (цех без входа).

### 3.3 Лендинг по токену

Страница: модуль, фасад, позиция профиля, ссылки «открыть папку» / PDF / комплект; опционально публичные ссылки Яндекса.

### 3.4 Гравировка

Регламент с технологом: минимальный размер QR, уровень коррекции ошибок (например H), контраст; выдача производству таблицы: профиль / слот / подпись / файл PNG/SVG QR.

## 4. Процесс «проектировщик → сервис → Диск»

1. Манифест структуры (проект, фасады, модули, **profiles со слотами**, компоненты и чертежи).
2. Идемпотентное создание дерева папок на Яндекс.Диске.
3. Загрузка файлов в слоты.
4. Регистрация записей в БД: stable id профиль-слота → ресурсы Диска.
5. Генерация **отдельного QR на каждый** `profile_slot`.
6. Пакет для производства.

## 5. Пример манифеста (YAML)

```yaml
project:
  code: PRJ-2026-014
  name: Объект X

facades:
  - code: FCD-1-5
    modules:
      - code: M-001
        name: Модуль типовой
        profiles:
          - slot: P1
            label: "Каркас левый"
            component_ref: CMP-RAIL-L
          - slot: P2
            label: "Каркас правый"
            component_ref: CMP-RAIL-R
          - slot: P3
            label: "Перемычка верх"
            component_ref: CMP-LINT-T
          - slot: P4
            label: "Перемычка низ"
            component_ref: CMP-LINT-B

components:
  CMP-RAIL-L:
    name: "Профиль несущий Л"
    disk_folder: "facades/FCD-1-5/modules/M-001/components/CMP-RAIL-L"
    primary_drawing: "чертеж.pdf"
```
