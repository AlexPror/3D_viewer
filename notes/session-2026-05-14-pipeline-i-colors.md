# Заметки сессии 2026-05-14 — пайплайн 3D и цвета STEP

Конспект для продолжения: Revit/КОМПАС, форматы, сервер, цвета в веб-вьювере.

## Продукт и роли

- **Revit 2022** в приоритете у команды; экспорт **FBX** часто легче STEP (сетка vs B-rep) — быстрее до картинки в браузере, но размер файла ≠ лёгкость сцены (треугольники).
- **КОМПАС** — возможное тестирование; пользователю ближе КОМПАС/Solid; **STEP из КОМПАСа** логичен для точной геометрии.
- **Сценарии 3D в приложении:** ознакомление, сборка в сцене, уточнение размеров — важно не смешивать «точность как в Revit» и измерения по **триангуляции** после экспорта (LOD, дуги).
- **Три уровня процесса:** (A) ссылка → браузер; (B) PDF + локальный CAD; (C) сложные случаи — Revit + телемост. Чтобы не тянуть только разработчика на экран — довести A до самообслуживания.

## Форматы и GLB

- **GLB «напрямую из Revit 2022»** штатно обычно нет → плагины или **FBX/IFC → конвертер → GLB**.
- **КОМПАС:** проверить экспорт glTF в своей версии; иначе **STEP** (уже поддерживается) или STEP→GLB на сервере/Blender.
- **Blender headless** — предсказуемая пакетная **FBX→GLB**; на сервере учесть RAM, очередь, таймауты (ноутбук как сервер = ограничить параллельность).
- Идея пайплайна: **КОМПАС → STEP, Revit → FBX**, на сервере нормализация (единицы, ось, LOD) и отдача во фронт **GLB**.

## Цвета и дерево STEP vs C3D Viewer

- **C3D** показывает цвета и дерево, потому что десктопный импортёр читает **XCAF/STEPCAF** и цвета из документа.
- **В нашем приложении (браузер, `viewer/src/lib/stepLoader.ts`):**
  - STEP читается через **`STEPCAFControl_Reader_1`**, `SetColorMode(true)`, `SetNameMode(true)`, `Transfer_1` в **`TDocStd_Document`**.
  - Дерево/метки: обход **`ShapeTool`** (GetComponents / GetShape / ChildIterator).
  - Экспорт в браузерный GLB: **`RWGltf_CafWriter.Perform_2`** — правильный класс решений для CAF→glTF.
  - **Важно:** при обходе для деталей вызывается **`XCAFDoc_ColorTool.SetColor`** с цветом из **палитры по имени детали** и отдельным цветом для «метизов» по ключевым словам — то есть **раскраска в основном синтетическая**, а не гарантированное сохранение цветов, уже попавших в ColorTool из файла после Transfer.
  - Fallback: **`STEPControl_Reader`** + один shape — без полноценного CAF-дерева/пер-частных цветов как в C3D.
- **Сервер `server/step_to_glb.py`:** CadQuery → STL → trimesh → GLB — **без XCAF-цветов и без дерева компонентов** в смысле STEP-метаданных.
- **`Viewer3D.vue`:** для GLB — цвета из материалов файла; опционально **JSON метаданные КОМПАСа** с сервера — отдельный канал раскраски.

## Идея на продолжение (не сделано)

- Чтобы вести себя ближе к C3D: **перед подстановкой палитры проверять**, есть ли у метки/геометрии уже цвет в **ColorTool** после импорта; **сохранять файл**, подставлять палитру только если цвета нет; политика для метизов отдельно.
